# Quick Wins

- Tables `qw_lideres`, `qw_ciclos`, `qw_envios`, `qw_itens`, `qw_avisos` are read-only to clients (SELECT grants only); every write goes through audited SECURITY DEFINER RPCs (`qw_salvar_item`, `qw_cancelar_item`, `qw_enviar`, `qw_triar`, `qw_atualizar_execucao`, `qw_ciclo_salvar`, `qw_abrir_ciclo`, `qw_fechar_ciclo`, `qw_lider_salvar`, `qw_lider_ativar`) logging to `mt_auditoria`. Nothing is deleted: leaders are deactivated, items cancelled, cycles archived.
- Leaders use only `@liberdademedicaedu.com.br` e-mails (CHECK); `user_id` is linked by verified e-mail on first login (auth trigger + `qw_vincular`).
- `is_lider_restrito` = active non-director leader with no `user_roles` and no `mt_usuarios` row; a director record always exempts its user. It only REDUCES access: `acesso_modulo` returns true solely for `quick_wins`, and the 36 previously open SELECT policies carry `AND NOT is_lider_restrito(auth.uid())`. Users with existing roles/profiles keep identical access. New open policies must add the same clause.
- Front: `useModuleAccess.liderRestrito` makes ModuleAccessGate redirect every other route to `/quick-wins` and the menu shows only that item. The `quick_wins` module is visible only to leaders, directors with leaders and Gov/CEO; an explicit `nenhum` override still hides it.
- One open cycle at a time (partial unique index); only Governance opens/closes. Closed cycle: items read-only except execution/result of approved items; archived cycle fully read-only.
- Max 10 non-cancelled items per submission (trigger). Classification is computed by trigger: quick_win when the investment band ceiling ≤ cycle limit, approval ≠ comite_ceo and deadline ≠ acima_90; converted items are always iniciativa_maior. The UI mirrors it in `src/lib/quickWins.ts` as a non-blocking warning.
- Draft: free editing. After sending, the leader edits only items in ajustar/devolvido and re-sends (they return to pendente). Triage: leader's director or Gov/CEO; comment required except approve.
- RLS: leader sees own leader/submission/items; director resolution prefers explicit user_id then an active director leader's user_id. Active qw_lider_diretores override the single-director fallback, and qw_itens.area_rotulo selects the authorized director. Item RLS and qw_triar share that predicate; qw_contexto exposes only visible areas and server-authorized triage IDs. Gov (mt_is_governanca, includes admin/super_admin) and CEO read all. Chair/director names come from qw_contexto, never from widening org tables.
- E-mails (director on send, leader on adjust/return) are queued in `qw_avisos` as `aguardando_remetente`; no sender is wired until transactional e-mail is configured.
- qw_email_chave normalizes case and removes dots only from the local part for Quick Wins registration/login matching; verified linking never overwrites an existing identity and skips ambiguous matches. The explicit initial Yuri alias links to the existing yuri.garcia account without changing authentication settings.
- qw_diretor_salvar is Governance-only and audited; relationships are inactivated, never deleted. Used area labels cannot be renamed; preserve their historical items and create a replacement relationship. Two active areas require a valid area on submission, not while creating a blank draft.
- Pending directors do not block drafting/submission: aguardando_diretor is reconciled on login, assignment and triage and exposed in Governance alerts. Explicit triagem_governanca routes directorless submissions to Governance without a pending flag. Notices are item-scoped and reconciled without real sending or widening their Governance-only read policy.
- Leader form is simplified: only `acao_proposta` ("Iniciativa proposta"), `observacao` ("Problema ou oportunidade que sanaria"), optional `investimento_estimado`, and Área only when the leader has more than one active director area. `qw_salvar_item` fills `titulo` with the first 80 characters of the initiative; `qw_enviar` requires only initiative + problem (and Área when >1 area), 1–10 items. Legacy columns (indicador, valores, objetivo, faixa, aprovação, prazo, mudança maior, responsável) stay in the database for history but are hidden from leader, triage, panel and CSV; the classification badge is hidden and its trigger keeps running on defaults.

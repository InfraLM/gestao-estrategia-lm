# Quick Wins

- Tables `qw_lideres`, `qw_ciclos`, `qw_envios`, `qw_itens`, `qw_avisos` are read-only to clients (SELECT grants only); every write goes through audited SECURITY DEFINER RPCs (`qw_salvar_item`, `qw_cancelar_item`, `qw_enviar`, `qw_triar`, `qw_atualizar_execucao`, `qw_ciclo_salvar`, `qw_abrir_ciclo`, `qw_fechar_ciclo`, `qw_lider_salvar`, `qw_lider_ativar`) logging to `mt_auditoria`. Nothing is deleted: leaders are deactivated, items cancelled, cycles archived.
- Leaders use only `@liberdademedicaedu.com.br` e-mails (CHECK); `user_id` is linked by verified e-mail on first login (auth trigger + `qw_vincular`).
- `is_lider_restrito` = active non-director leader with no `user_roles` and no `mt_usuarios` row; a director record always exempts its user. It only REDUCES access: `acesso_modulo` returns true solely for `quick_wins`, and the 36 previously open SELECT policies carry `AND NOT is_lider_restrito(auth.uid())`. Users with existing roles/profiles keep identical access. New open policies must add the same clause.
- qw_email_chave normalizes case and removes dots only from the local part for Quick Wins registration/login matching; verified linking never overwrites an existing identity and skips ambiguous matches. The explicit initial Yuri alias links to the existing yuri.garcia account without changing authentication settings.

- No triage (nov/2026): leaders send = response registered; they edit, add, cancel and re-send while the cycle is open (closed/archived = read-only). `qw_enviar` considers only items with a filled initiative (others are ignored, never blocking): requires 1–10 of them, each with justification and the three ICE scores; "Tem custo?" and its value are optional (blank shows "—"; % with cost counts only Sim); no área/diretor requirement and no notices. Triage/execution/director columns, `qw_triar`, `qw_lider_diretores` and `qw_avisos` stay for history but are unused by the UI.
- Access: the module opens only for active registered leaders (own form) and Governance/admin (`mt_is_governanca`). `qw_pode_ler_lider`/`qw_pode_ler_item` = Governance OR own row; directors and CEO no longer read other leaders. `qw_meu_perfil.diretor` is always false. Front: `canAccessQuickWins` = lider_id || governanca; liderRestrito still redirects to `/quick-wins`.
- Tabs: "Formulário" (10-row table; read-only preview for non-leader admins; locked notice without an open cycle), and for Governance only "Painel" (respondent %, total, % with cost, average ICE, ICE ranking, filters cadeira/cargo/líder/custo, sortable table, CSV) and "Administração" (cycles, leaders without director field).
- Items store `tem_custo`, `investimento_estimado` (value), ICE `ice_impacto`/`ice_confianca`/`ice_facilidade` (1–5, validated in `qw_salvar_item`) and generated `ice_score`; `titulo` = first 80 chars of the initiative. Empty rows are ignored; cleared saved rows are cancelled, never deleted.
- Invitation e-mail (Governance, Administração tab → "Convite por e-mail"): approved text signed by Naira via `rotina-avisos-enviar` action `qw_convite` (Gmail sender). `modo:"teste"` sends to up to 5 corporate addresses and records nothing; `modo:"lideres"` sends to active leaders of the open cycle once each, recorded in `qw_convites_email` (service-role writes, Governance reads). Deadline = open cycle `data_fechamento`. The e-mail link `/quick-wins/formulario` renders only the form (no AppLayout/sidebar) behind ModuleAccessGate and is an allowlisted login return.

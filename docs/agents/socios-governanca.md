# Sócios, Governança e IA de planejamento

- Desejos dos Sócios lives in `socios_*` tables; access is closed by default and comes from `socios_participantes` (respondente / pode_ver_consolidado), not `usuario_acessos` nor super_admin — answers include confidential profit-distribution data and never feed AI.
- Sócio submission status, versions, and reopening only change through `socios_enviar` / `socios_reabrir`; a trigger enforces the deadline and protects those fields.
- Trade-off scoring lives in pure functions in `src/lib/sociosTradeoff.ts`, recomputed on read and never stored.
- Sócios can answer without login through per-participant secret links (`socios_links`); lookups use the SHA-256 hash, and the raw token column is never granted to client roles, only returned to consolidators by `socios_links_painel`, so Governance can re-copy links without exposing them. Anon RPCs `socios_link_*` resolve the token server-side via `socios_link_acesso` (logs each open/save/send), validity is set at generation, and `socios_vincular` later moves a provisional user_id's answers to the real account. Links are always built on the published URL (`src/lib/linksSocios.ts`) because preview URLs require a Lovable login.
- Sócios normalize versioned portfolio answers on read; shared open-answer helpers feed consolidation, submission documents and CSV. The token-validated load RPC exposes only the product-results content key.
- Governança connection test is a read-only edge function returning only aggregate counts; admin/super_admin only, token in secret GOV_EXPORT_TOKEN, never returned or logged.
- Governance mirrors use service-role upserts, never deletes; normalized names map to multiple chairs through gov_responsaveis_map_cadeiras (map.mt_cadeira_id deprecated). Hourly cron is incremental; manual/daily sync are full via x-sync-modo. Successful syncs publish deliberations as GOV codes via service-only gov_publicar_deliberacoes, preserving manual data and D-NNN.
- Planning report and diagnostic revisions (`planejamento_revisoes`): AI only writes drafts through `planejamento-gerar` (Governança, 3/month/type); every claim cites an input code, unknown codes become [sem fonte] and block approval; only `planejamento_aprovar` makes a revision current, keeping history.
- Document content revisions use conteudo_revisoes and conteudo_revisao_itens independently of AI planning reports. Drafts are Governance/CEO-only, published snapshots follow Strategy module access; only mt_is_governanca can decide/publish through locked audited RPCs. Manual edits reset their item to pending; rejected values retain baseline, and publication substitutes the previous revision. BSC/OKRs are excluded from keys and publication.
- Strategic link suggestions live in a private queue (`estrategia_sugestoes`) with source-aware RLS; all source reads in `estrategia-sugerir` use the caller JWT, never service-role. Manual generation (20 sources, sequential batches of 10) uses the same report model; rejected source/target pairs persist unless explicitly regenerated. Only the transactional `estrategia_revisar_sugestoes` RPC creates approved links, validates active targets and readable sources, locks selected rows and records reviewer/time; AI never writes links. Audit tables are append-only to clients. Provider denials persist in execution history and stop further calls.

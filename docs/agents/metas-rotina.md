# Metas, OKRs, Rotina semanal e Projetos

- Metas 2S26 and weekly check-ins share `mt_*` via `useMetasBase`.
- Cadence metadata lives on mt_indicadores, independent of V/S/E; Government/CEO edits use mt_frequencia_salvar and audited guards, with source floor and slower-speed checks. Calendar helpers and mt_frequencia_devida use the ordinal Monday; rotina_retrato_ciclo returns due-only chair-authorized period snapshots, preserved at first send. Critical exceptions are created only by submitted checkout trigger, monthly distinct-period readings advance their normal streak and audit restoration. Existing authorized situation projection is wrapped to append only period/exception flags, never private cause/impact/action. Calendar-aware evaluators hold last readings between scheduled months; matrix skips off-calendar cells when counting consecutive deviation alerts.
- KPIs, KRs and Cesta share `mt_indicadores` by `origem`; each has `tipo_apontamento` (valor_mensal/valor_periodo/entrega, Governança-only, audited trigger). Evaluation is computed on read only via `avaliarPorTipo` (wraps `avaliarKpiBsc`; latest declaration/status from Lançar mês or sent checkout wins) so form, Lançar mês, Painel, Visão, Matriz and AI report never diverge.
- No weighted monthly score on screen: `mt_envios.nota` and `mt_pesos_vigencia` are kept only as history. Per-director metric is weekly-cycle conformity (`src/lib/conformidade.ts`, completude stored in checkout JSON at first send, read via `rotina_conformidade` visible to Governança, CEO and every chair holder). Conforme = sent by Monday 23:59 São Paulo AND completude ≥ 90%; due cycles start at cycle 2026-10-26; status report counts one item per open principal-chair project (file + three lights), never blocking send.
- Iniciativa "atrasada" is computed on read (`statusEfetivo`), never stored.
- Metas: reads need login (`mt_email_corporativo`); cadastro writes need `mt_is_governanca`, enforced in RLS.
- Monthly launch: values in `mt_lancamentos` keyed by indicador+competência+revisão; reopening (`mt_reabrir`) copies into a new revisão — never overwrites a closed month. Monthly notes (`mt_envios`) are visible only to Governança, CEO and the own chair.
- Weekly cycle S = checkin of S (priorities) + checkout of S−7 (retrospective) in `mt_checkins` (cadeira+semana+tipo); both rows are sent together in one upsert with one envio_token, one deadline (`prazoCiclo`) and one seal (`seloCiclo`). In-app reminder remains; email configuration/outbox lives separately, Governance-only and default-off. Recipient projection requires active chair, matching mt_usuarios assignment, valid profile email and routine read access. No private content enters emails; sender readiness stays false until the domain and managed sender adapter are configured. Weekly email deep links preserve only validated Monday dates and allowlisted login returns.
- Director transparency is a Governança-controlled audited switch (default off). Status and KPI situations reach other chairs only through status RPCs (`rotina_status_ciclos`, `rotina_situacoes_kpi`); full weekly content of other chairs only when the switch is on. Contacts, attachments and reserved notes never widen.
- Critical deviation in the matrix (pure `marcarCriticos`): 2+ consecutive Off-track periods and attainment below 70%; plan-without-initiative is a separate alert.
- Action links (BSC/KR/cesta/projeto) travel as `vinculos` in weekly JSON; initiatives keep the single `indicador_id` as principal and secondary links live in `mt_acao_vinculos` via `rotina_vincular_iniciativa`. Delivery owners come from organogram children of the cargo linked by `mt_cadeira_id` (Governança-only, trigger-enforced).
- Minutes pendencies stay listed until closed upstream; the director status lives in checkout JSON `atas` and carries from the last sent checkout. Assignment uses `gov_acoes.responsavel_email` when present, else the name map.
- Checkout KPI numbers are live until first send, then stored in `kpis_retrato`; `src/lib/rotinaSemanal.ts` normalizes old/new JSON. Plans → initiatives only via idempotent `rotina_criar_iniciativa`; risks in `mt_rotina_riscos` (immutable text); outside e-mails only in `mt_rotina_contatos`, never in weekly JSON.
- Checkout extras are optional structured deliveries in extras_lista; legacy extras/aprendizados/proxima are read-only history, never erased. Extras validation gates only malformed entered rows at send, not completeness; Governance reason summaries group sent checkouts by Sunday month and chair. AI report uses an explicit extras-only projection, never learns/focus, contacts or reserved notes.
- Projects: principal chair `projetos.cadeira_id` set only via Governança RPC (text `diretor` is a suggestion) + support chairs; impact links in `projeto_vinculos` (legacy objetivos/krs read-only). Status reports only in last-cycle-of-month checkout (`ultimoCicloDoMes`), principal chair, open statuses; missing file is pending, not a blocker; edits versioned; files: chair/Governança/CEO. Status changes only via `projeto_confirmar_situacao` or `projeto_registrar_decisao` (Gov/CEO, SR codes in Contexto).
  Exception: `/pmo/atualizar-status` persists open-project changes through `pmo_atualizar_status` only (PMO read access plus CEO, explicit editor or legacy PMO writer; no broad RLS changes). Transactional batch locks rows, rejects stale versions, limits 100 rows, and stores actor/time/before/after in append-only audit. Closed statuses cannot be set or reopened there; SR decisions remain mandatory. Direct update notice appears on the status-report farol. Mirror improvements remain read-only; browser-only legacy improvements are not treated as shared records.

- Impacto Estratégico (`/impacto-estrategico`) hosts tabs Objetivos (drill-down via DesdobramentoObjetivo), Por vínculo and Cadastro de iniciativas; `/pmo/vinculos` redirects there. Ata actions and D/GOV decisions link to objectives/indicators only through `estrategia_vinculos_gov` (Governança/CEO edit), never by changing synced records; decisions are milestones and never count as late.
- Objective finance widgets read orc_* with server-enforced PMO access plus Gov/CEO/chair director. Default-zero project budget is not approved funding: orc_projeto_budget requires a release source and audited Gov/CEO save. Principal attribution resolves direct/indicator objective once; ambiguous/missing principals get no allocation. Cost center proposals are separate from Governance confirmation, with exclusive confirmed centers until an explicit allocation rule exists. Monthly mirror import replaces totals atomically, never adds repeated imports; config starts off. KPI 2030 defaults come from exact-name matches and percentage formatting in uploaded rev.17.09.26; database override is Gov/CEO only. Latest numeric observations exclude narrative/date parsing; situation uses avaliarPorTipo for the current month, while historical observations retain their own date or an unknown-period notice.
- Processes in Impacto Estratégico: local `processos` list until the `proc_espelho_*` mirror has rows, then the mirror replaces it and divergences show to Governança. Maturity shown = level/gate (assessment score only in detail); ICEP shown only as link confidence; impact = Direct/Indirect + grade today→target, 12 axes only in detail. Mirror KPIs reach KPI/KR/cesta only via Governança-confirmed `proc_kpi_correspondencia`; chairs via confirmed `proc_diretoria_cadeira`. Improvements: only in progress/implemented, late when forecast passes. `processos-sync` (also `?teste=1`) refuses unless `proc_integracao_config.ativo` and PROC_EXPORT_URL/TOKEN exist; never confirms mappings.

- Portfolio strategic links use `portfolio_vinculos` as the authoritative projection for project/initiative impact. Existing explicit links are migrated as proposed legacy records; old principal and secondary tables remain for routine compatibility, but impact reads use only active non-removed authoritative links. Source RLS gates reads; `portfolio_revisar` locks sources/links, checks Governança/CEO/principal-chair authorization and audits manual edits/validation/removal. Manual edits validate; removed pairs remain tombstones and validated sources are never reprocessed.
- Human edits to portfolio links (target, rationale, impact, add/remove, single or batch) keep or return the link to 'proposto' and stamp editado_*; only 'validar'/'salvar_validar' validate. Any human-edited or validated source is protected from AI reprocessing, server-side.
- `portfolio-vincular` reads only caller-visible sources and active/current-semester targets; legacy references take precedence over report-model AI (20 sources, sequential batches of 5, 1–4 AI links). New-item triggers enqueue every creation path; the signed-in creator processes their pending jobs one at a time. No automatic retries after terminal failures, no Sócios, attachments, reserved comments or contacts sent to AI. Summary counts include proposed and validated links, with pending count and badges.
- Voluntary "outros KPIs" are flagged `voluntario` in kpis_retrato/kpis_resposta: excluded from completude and pendências, never change frequency; only converting to desvio crítico makes them count. The rotina dashboard reads KPI values for all chairs via the `rotina_dashboard_kpis` projection (values/situation/period/meta only, gated by rotina_ve_todas + rotina read), while priorities/extras still come from mt_checkins RLS so the transparency switch keeps governing them.
- Assigned risks/impediments publish at sent check-in, enqueue once per recipient/item through rotina_avisos_envios (impedimento), and enter recipient obligations only next cycle. Protected per-cycle response records require plan/date/status and justification for nao_procede; reopened items invalidate older responses. Send trigger adds only completeness counts to checkout JSON. ImpedimentosRecebidos and AtividadesRotina read chair-scoped RPCs; no transparency-based widening, no external contacts/financial/Sócios data. Audit stores before/after; sending remains queued until the managed sender is connected.
- Stacking window: atas and priorities stack only when origin (meeting date, check-in week) or Governance reactivation is within 3 months (`rotina_dentro_janela`, mirrored in `src/lib/acoesEntrega.ts`); older open items move to the Governance "Pendências antigas" list and leave completeness. Ata actions reach a chair only when addressed (email/name map or Governance assignment in `rotina_pendencias_gestao`); ownerless ones wait in `rotina_atas_aguardando`. Assigned impediments ignore the window and stack until resolved/closed. AI (`rotina-pendencias-sugerir`) only writes Governance-readable rows in `rotina_pendencia_sugestoes`; bulk actions apply item by item through the same audited RPC. All Governance actions go through audited `rotina_pendencia_gerir`, never by editing synced records.
- Checkout item-2 action deliveries live per action in `rotina_acoes_entrega` (audited, saved via `rotina_acao_salvar`, never in weekly JSON nor completeness); "em andamento" carries over without the 3-month window until concluded or cancelled with reason; reads follow `rotina_pode_ler_checkin` (transparency switch) plus principal-chair project holders.

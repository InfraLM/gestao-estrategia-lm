# AGENTS.md

Area rules live in nested AGENTS.md files; read the one for the folder before changing files there:
- `docs/agents/metas-rotina.md` — Metas, OKRs, Cesta, Lançamentos, weekly cycle, transparency, projects (applies to src/pages Metas*/Semanal*/Hubs/Matriz*, src/lib rotina/avaliacao/matriz/projetos, mt_* SQL).
- `docs/agents/socios-governanca.md` — Desejos dos Sócios, Governança integration, AI planning revisions.
- `src/components/AGENTS.md` — layout. `src/components/estrutura/AGENTS.md` — organogram and canonical identities; apply directory rules across forms.

- Phase 1 spaces use six isolated tables and additive `fase1_*` auth helpers; new modules default closed, with owner/director read exceptions enforced server-side without changing legacy module access.
- Pré-Offsite form structure lives in offsite_config (PADRAO is only fallback). Admin edits use offsite_config_rascunhos + offsite_config_publicar: add/reorder/archive ids, never delete, with audited answer migration; protects answers keyed by names.
- Pré-Offsite uses isolated offsite_* tables, verified chair participants and protected admins; admin status never authorizes a personal response. Versioned RPCs/config preserve privacy and old answers through new namespaces and retired IDs in history. Shared visibility projections drive empty read-only admin previews, never impersonation; consolidation/Excel stay admin-only with no legacy permission or KPI writes.
- Cadence calendar (CalendarioApontamento) uses pure draft/load helpers and shared São Paulo next-Monday projections preserving sent cycles; batch saves per row via mt_frequencia_salvar, keeping failed drafts.
- Strategic reference URLs use linksEstrategicos; Contexto and Insights select sheets from the codigo query parameter using replace navigation and only RLS-visible records, preserving filters and existing access gates.
- Strategic spaces read via RLS; Contexto, Insights Sócios, Incentivos read-only; CestaInsights edits only adherence fields (incentivos editors/admin). No general exports.
- Editable static content is JSON per key in `conteudo_editavel` via `useConteudo`, static defaults as fallback.
- Diagnosis and formulation defaults are shared in conteudoPadroes; conteudo_revisoes snapshots and items govern diag.* and non-OKR estr.*. Manual writes only suggest via revisao_sugerir; only Governance decision/publication RPCs apply content, preserve rejected baseline values and audit. Revision providers project historical/draft values without affecting BSC/OKRs; client direct writes are trigger-blocked.
- Per-user module overrides live in `usuario_acessos`; restrictive RLS caps existing row-scoped permissions, while moduleAccess/useModuleAccess mirror those caps in navigation and editing. Missing overrides preserve legacy access; only super_admin manages overrides and retains full access.
- Administrator invitations are stored in `usuario_convites` and applied by an Auth lifecycle trigger only after email verification; email sending validates the caller server-side, and Google uses the managed Lovable helper to avoid impersonation and preserve preview support.
- Shared invitation links use the public auth page; acceptance validates the signed-in verified email server-side and is idempotent for the same user, so existing accounts can accept without granting access to link holders.
- Cadastro screens live inside the list they feed (query-param tabs via AbasPagina); old routes redirect instead of being deleted, so bookmarks keep working.
- Portfolio link reviews only add 'ia_revisao' proposals and flag unsupported ones as 'revisar' (never delete/validate); each source keeps at most one 'principal' impact, enforced server-side.
- Weekly extra deliveries use additive extras_lista JSON with reason ID and historical label/detail-requirement snapshots; mt_extra_motivos is Governance-managed with soft deactivation, and a send trigger validates optional rows. Shared extras views preserve legacy text; monthly aggregation reads only RLS-visible sent checkouts, preventing transparency expansion.
- Weekly notification configuration/outbox is Governance-only and default-off; SQL schedules use São Paulo times and chair-scoped aggregate-only recipient projection. Sender readiness must remain false until Lovable transactional-email scaffolding and a wake-on-enqueue sender adapter are deployed, preventing unprocessed mail or accidental director sends. Future channels extend the outbox, not the weekly submission/compliance rules.
- KPI cadence is independent of V/S/E: shared Monday-calendar helpers and server cycle snapshots carry reporting-period metadata; first-send snapshots are immutable and due-only. Cadence edits are Governance/CEO-only and audited; exception escalation is chair-owned, persisted on submission, counted monthly and restored by idempotent distinct-period normal readings without a recurring job. Aggregate situation projections preserve the existing privacy gate and add only period/exception metadata.
- Assigned impediments retain immutable source text in mt_rotina_riscos; cycle submission publishes and deduplicates the shared outbox. Responses/reopening use audited chair-authorized RPCs and per-cycle response records; recipient completeness is enforced at send. Activity projections and restrictive risk RLS ignore transparency, limiting directors to origin/recipient chairs while Governance/CEO see all; private plans never enter shared weekly JSON.
- FormField and SaveFeedback provide opt-in accessible form presentation; required cues mirror existing validators without native validation changes. Weekly section navigation preserves mounted fields and combined submission; exclusiveAction guards only concurrent browser actions, never changes persisted idempotency.
- Dimension lights in /status-report are controlled draft values saved as nullable farois_dimensoes on append-only status_reports; server triggers validate and audit before/after into mt_auditoria. Historical NULL means unrecorded, never green; weekly mt_status_projetos and its versioning remain separate.
- Cycle preparation keeps verified-email chair invitations separate from roles; chair and cadence AI suggestions require explicit audited approval, and spreadsheet imports use existing protected budget/target RPCs. This prevents preparation from confirming AI outputs or clearing historical blank values.
- Unsaved-change guards are presentation-only and searchable Select options retain canonical stored values; neither mechanism changes submission, cadence, persistence or permissions.
- Objective finances use protected orc_* tables/RPCs: proven released budgets separate from default-zero legacy project estimates, allocated once by resolved principal portfolio link. Confirmed exclusive cost-center mappings feed cumulative monthly mirrors; no implicit sharing/rateio. Budget exports use a disabled caller-authenticated manual sync and atomic replacement imports. KPI 2030 targets are additive text metadata, edited Gov/CEO via audited RPC; current KPI assessment reuses avaliarPorTipo without treating 2030 as current-period targets.
- Fit Finder stores aggregate directorates separately from unique directorate/chair pairs in fitfinder_diretoria_cadeiras (legacy singular table deprecated); fitfinder_pode_ler defaults to Gov/CEO only with an optional default-off confirmed-chair switch. Shared server-derived access gates hide the tab and shortcuts without widening estrutura access; sync masks groups < 3, never overwrites human mappings or stores individual data.
- Sócios consolidated axes use a dedicated lane component and pure identity/consensus/input helpers, leaving individual trade-off rulers and persisted scoring unchanged; optional portfolio details stay in the existing answer JSON and shared history/export helpers.
- Legacy portfolio responsibility edits persist explicit person IDs against database UUIDs exposed by useProjetosDB; canonical projections are memoized, original labels/principal chairs and separate status-report histories remain untouched. This prevents local-only success and name-based reassignment.
- BSC Rev.03 keeps KPI/objective ids on renames (codigo_anterior/nome_anterior), archives merged or removed KPIs (status 'arquivado', fundido_em) and never deletes them; Rev.02 static details are looked up via src/lib/bscRev03 by current or previous name, and parent metrics live in bsc_metricas_mae outside objectives. This preserves history, links and saved answers.
